Building Production REST APIs with NestJS

Case Study: Student Management API

Welcome to this complete, cookbook-style masterclass on architecting, implementing, and securing a battle-tested Student Management System (SMS) REST API using NestJS, TypeScript, and PostgreSQL.

⚙ NestJS Architecture

A structured, enterprise Node.js framework inspired by Angular. Combines Object-Oriented Programming (OOP), Functional Reactive Programming (FRP), and pure TypeScript with robust Dependency Injection.

• Modules • Controllers • Services • DTOs

👥 Multi-Role Domain (RBAC)

Enforces strict Role-Based Access Control across three educational personas:
• ADMIN (Registrar / Dean: registers & manages student records)
• TEACHER (Faculty: manages grades & courses)
• STUDENT (Learner: views profile & enrollment)

Built with production-grade engineering principles:
• Strict runtime schema validation (Joi + class-validator)
• Database migrations with TypeORM & ACID transactions
• JWT auth, Throttling, Winston structured logs & Docker

NestJS Core Pillars & Request Lifecycle

Architecture

In raw Express, requests travel through an unconstrained chain of custom middleware. NestJS enforces a deterministic, strongly-typed lifecycle where each layer has a single, well-defined architectural responsibility.

Client Request
→
1. Middleware
→
2. Guards (Auth/RBAC)
→
3. Interceptors (Pre)
→
4. Pipes (Validation)
→
5. Controller Handler
→
6. Service (Logic/DB)
→
7. Interceptors (Post)
→
8. Exception Filter

1. Modules (@Module())

Boundary containers organizing your application domain into modular graphs. Declares controllers, providers, imports, and exports.

2. Controllers (@Controller())

Routes HTTP methods (GET, POST, PATCH, DELETE) to handlers. Extracts params, query strings, and request bodies. Delegates immediately to services.

3. Providers (@Injectable())

Contains business logic, database queries, password hashing, and third-party integrations. Injected automatically via NestJS Inversion of Control (IoC).

💡 TIP: Why Guards Execute Before Pipes: Guards check authentication and permissions before Pipes validate request bodies. If an unauthenticated client sends a malicious 5MB payload, the Guard blocks it immediately with 401 Unauthorized before the server spends CPU parsing or validating the body!
⚠️ PITFALL: Fat Controllers: Never put business calculations, password hashing, or database queries inside your controller methods. Keep controllers ultra-thin: parse incoming parameters, invoke the service, and return the response.

  JWT_EXPIRES_IN: Joi.string().default('1h'),
  BCRYPT_SALT_ROUNDS: Joi.number().min(10).max(14).default(10),

Data Models & TypeORM Entities

Domain Layer

In our architecture, base credentials (email, hashed password, system role) live on the User entity, while academic records live on the Student entity linked via a 1-to-1 relational mapping with TypeORM. 

src/common/enums/role.enum.tsexport enum Role {
  ADMIN = 'ADMIN',       // Registrar, System Administrators
  TEACHER = 'TEACHER',   // Faculty & Instructors
  STUDENT = 'STUDENT',   // Enrolled Learners
}
src/users/entities/user.entity.tsimport { Entity, PrimaryGeneratedColumn, Column, CreateDateColumn, UpdateDateColumn, DeleteDateColumn, OneToOne } from 'typeorm';
import { Exclude } from 'class-transformer';
import { Role } from '../../common/enums/role.enum';
import { Student } from '../../students/entities/student.entity';

@Entity('users')
export class User {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ unique: true, length: 150 })
  email: string;

  @Column()
  @Exclude() // Automatically stripped from JSON responses
  passwordHash: string;

  @Column({ type: 'enum', enum: Role, default: Role.STUDENT })
  role: Role;

  @CreateDateColumn()
  createdAt: Date;

  @UpdateDateColumn()
  updatedAt: Date;

  @DeleteDateColumn() // Enables soft-delete (preserves audit trail)
  deletedAt?: Date;

  @OneToOne(() => Student, (student) => student.user)
  student?: Student;
}
src/students/entities/student.entity.tsimport { Entity, PrimaryGeneratedColumn, Column, CreateDateColumn, UpdateDateColumn, DeleteDateColumn, OneToOne, JoinColumn } from 'typeorm';
import { User } from '../../users/entities/user.entity';

@Entity('students')
export class Student {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ unique: true, length: 30 })
  rollNumber: string; // e.g. "CS-2026-042"

  @Column({ length: 60 })
  firstName: string;

  @Column({ length: 60 })
  lastName: string;

  @Column({ length: 100 })
  department: string;

  @Column({ type: 'int' })
  enrollmentYear: number;

  @Column({ default: 'ACTIVE' })
  status: 'ACTIVE' | 'GRADUATED' | 'SUSPENDED';

  @CreateDateColumn()
  createdAt: Date;

  @UpdateDateColumn()
  updatedAt: Date;

  @DeleteDateColumn()
  deletedAt?: Date;

  // 1-to-1 link with User authentication account
  @OneToOne(() => User, (user) => user.student, { onDelete: 'CASCADE' })
  @JoinColumn({ name: 'userId' })
  user: User;

  @Column()
  userId: string;
}
💡 TIP: Soft Delete Protection: Using @DeleteDateColumn() allows calling studentRepo.softDelete(id). Instead of permanently destroying student history, TypeORM sets deletedAt = NOW() and automatically filters out deleted rows from standard queries!

Database Setup with TypeORM & Migrations

Database Layer

Connecting NestJS to PostgreSQL requires @nestjs/typeorm. For production safety, we configure dynamic asynchronous module loading via ConfigService and manage database schema changes using migrations.

Step 1: DTO & Global Validation Pipe

Registration Pipeline

A DTO (Data Transfer Object) defines the exact network contract for incoming HTTP payloads. Using class-validator and class-transformer, data is sanitized and validated before hitting your controller. 

src/students/dto/create-student.dto.tsimport { IsEmail, IsNotEmpty, IsString, MinLength, Matches, IsInt, Min, Max } from 'class-validator';
import { Transform } from 'class-transformer';
import { ApiProperty } from '@nestjs/swagger';

export class CreateStudentDto {
  @ApiProperty({ example: 'alex.rivera@university.edu', description: 'Institutional email' })
  @IsEmail({}, { message: 'Must be a valid email format' })
  @Transform(({ value }) => value?.trim().toLowerCase()) // Normalize input
  email: string;

  @ApiProperty({ example: 'Pass123!Secure', description: 'Min 8 chars with upper, lower, & number/symbol' })
  @IsString()
  @MinLength(8, { message: 'Password must be at least 8 characters' })
  @Matches(/((?=.*\d)|(?=.*\W+))(?![.\n])(?=.*[A-Z])(?=.*[a-z]).*$/, {
    message: 'Password must contain uppercase, lowercase, and a number or symbol',
  })
  password: string;

  @ApiProperty({ example: 'Alex', description: 'Legal first name' })
  @IsString()
  @IsNotEmpty({ message: 'First name cannot be empty' })
  @Transform(({ value }) => value?.trim())
  firstName: string;

  @ApiProperty({ example: 'Rivera', description: 'Legal last name' })
  @IsString()
  @IsNotEmpty({ message: 'Last name cannot be empty' })
  @Transform(({ value }) => value?.trim())
  lastName: string;

  @ApiProperty({ example: 'CS-2026-042', description: 'Format: CS-YYYY-XXX' })
  @IsString()
  @Matches(/^CS-\d{4}-\d{3}$/, { message: 'Roll number must follow format CS-YYYY-XXX' })
  rollNumber: string;

  @ApiProperty({ example: 'Computer Science' })
  @IsString()
  @IsNotEmpty()
  department: string;

  @ApiProperty({ example: 2026, minimum: 2020, maximum: 2035 })
  @IsInt()
  @Min(2020)
  @Max(2035)
  enrollmentYear: number;
}
src/students/dto/update-student.dto.tsimport { PartialType, OmitType } from '@nestjs/swagger';
import { CreateStudentDto } from './create-student.dto';

// PartialType makes all fields optional for PATCH requests
// OmitType prevents client from modifying the password via student update
export class UpdateStudentDto extends PartialType(
  OmitType(CreateStudentDto, ['password'] as const),
) {}
src/main.ts (ValidationPipe Setup)import { ValidationPipe } from '@nestjs/common';

app.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,              // Strips unexpected fields injected by attackers
    forbidNonWhitelisted: true,  // Throws 400 Bad Request on unknown fields
    transform: true,             // Automatically converts string params to types
    transformOptions: { enableImplicitConversion: true },
  }),
);
⚠️ CRITICAL PITFALL: Mass-Assignment Attack: Without whitelist: true, a malicious caller could POST { "role": "ADMIN" } or { "isSuperUser": true } in the request body. If passed directly to the database, their privileges would be silently escalated!
💡 TIP: PartialType Inheritance: PartialType from @nestjs/swagger inherits both validation rules and Swagger schemas, automatically flagging all fields as optional without duplicating code.

Step 2: Full CRUD REST Controller

Registration Pipeline

The controller defines HTTP route verbs, route security guards, Swagger documentation, and delegates execution to StudentsService. It stays thin with zero embedded business logic. 

src/students/students.controller.tsimport { Controller, Post, Get, Patch, Delete, Body, Param, Query, HttpCode, HttpStatus, UseGuards, ParseUUIDPipe } from '@nestjs/common';
import { ApiTags, ApiOperation, ApiResponse, ApiBearerAuth, ApiParam } from '@nestjs/swagger';
import { StudentsService } from './students.service';
import { CreateStudentDto } from './dto/create-student.dto';
import { UpdateStudentDto } from './dto/update-student.dto';
import { JwtAuthGuard } from '../auth/guards/jwt-auth.guard';
import { RolesGuard } from '../auth/guards/roles.guard';
import { Roles } from '../auth/decorators/roles.decorator';
import { Role } from '../common/enums/role.enum';

@ApiTags('Students')
@ApiBearerAuth('JWT-auth')
@UseGuards(JwtAuthGuard, RolesGuard) // Protects all routes in this controller
@Controller('students')
export class StudentsController {
  constructor(private readonly studentsService: StudentsService) {}

  @Post('register')
  @HttpCode(HttpStatus.CREATED)
  @Roles(Role.ADMIN) // Only ADMIN role can register student profiles
  @ApiOperation({ summary: 'Register a new student and create auth user account' })
  @ApiResponse({ status: 201, description: 'Student registered successfully' })
  @ApiResponse({ status: 400, description: 'Validation failed' })
  @ApiResponse({ status: 409, description: 'Email or Roll number conflict' })
  async register(@Body() createStudentDto: CreateStudentDto) {
    return this.studentsService.registerStudent(createStudentDto);
  }

  @Get()
  @Roles(Role.ADMIN, Role.TEACHER)
  @ApiOperation({ summary: 'List all enrolled students with pagination' })
  async findAll(@Query('page') page = 1, @Query('limit') limit = 10) {
    return this.studentsService.findAll(+page, +limit);
  }

  @Get(':id')
  @Roles(Role.ADMIN, Role.TEACHER, Role.STUDENT)
  @ApiOperation({ summary: 'Get single student profile by UUID' })
  async findOne(@Param('id', ParseUUIDPipe) id: string) {
    return this.studentsService.findOne(id);
  }

  @Patch(':id')
  @Roles(Role.ADMIN)
  @ApiOperation({ summary: 'Update student profile details' })
  async update(
    @Param('id', ParseUUIDPipe) id: string,
    @Body() updateStudentDto: UpdateStudentDto,
  ) {
    return this.studentsService.update(id, updateStudentDto);
  }

  @Delete(':id')
  @HttpCode(HttpStatus.NO_CONTENT)
  @Roles(Role.ADMIN)
  @ApiOperation({ summary: 'Soft-delete a student by UUID' })
  async remove(@Param('id', ParseUUIDPipe) id: string) {
    return this.studentsService.remove(id);
  }
}
⚠️ PITFALL: Forgetting ParseUUIDPipe: Without ParseUUIDPipe, sending an invalid string like GET /students/abc-123 passes the string to Postgres, crashing with a database driver error (500 Internal Server Error) instead of a graceful 400 Bad Request.
💡 TIP: HTTP 204 No Content on DELETE: Use @HttpCode(HttpStatus.NO_CONTENT) for DELETE endpoints that do not return a body. This matches official REST semantics.

Step 3: Service Business Logic & ACID Transactions

Registration Pipeline

The service layer contains domain logic, checks for duplicate accounts, hashes passwords with bcrypt, and executes atomic database writes across the User and Student tables using a TypeORM transaction. 

src/students/students.service.tsimport { Injectable, ConflictException, NotFoundException, Logger } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository, DataSource } from 'typeorm';
import { ConfigService } from '@nestjs/config';
import * as bcrypt from 'bcrypt';
import { Student } from './entities/student.entity';
import { User } from '../users/entities/user.entity';
import { Role } from '../common/enums/role.enum';
import { CreateStudentDto } from './dto/create-student.dto';
import { UpdateStudentDto } from './dto/update-student.dto';

@Injectable()
export class StudentsService {
  private readonly logger = new Logger(StudentsService.name);

  constructor(
    @InjectRepository(Student)
    private readonly studentRepository: Repository<Student>,
    @InjectRepository(User)
    private readonly userRepository: Repository<User>,
    private readonly dataSource: DataSource,
    private readonly configService: ConfigService,
  ) {}

  async registerStudent(dto: CreateStudentDto) {
    this.logger.log(`Initiating registration for student email: ${dto.email}`);

    // ACID Transaction ensures atomic creation: both succeed or both rollback
    return await this.dataSource.transaction(async (manager) => {
      // 1. Conflict Check: Email
      const emailExists = await manager.findOne(User, { where: { email: dto.email } });
      if (emailExists) {
        throw new ConflictException(`Email '${dto.email}' is already registered in the system.`);
      }

      // 2. Conflict Check: Roll Number
      const rollExists = await manager.findOne(Student, { where: { rollNumber: dto.rollNumber } });
      if (rollExists) {
        throw new ConflictException(`Roll number '${dto.rollNumber}' is already allocated.`);
      }

      // 3. Password Hashing with Bcrypt
      const saltRounds = this.configService.get<number>('BCRYPT_SALT_ROUNDS', 10);
      const passwordHash = await bcrypt.hash(dto.password, saltRounds);

      // 4. Create User Authentication Record
      const user = manager.create(User, {
        email: dto.email,
        passwordHash,
        role: Role.STUDENT,
      });
      const savedUser = await manager.save(User, user);

      // 5. Create Linked Student Profile
      const student = manager.create(Student, {
        userId: savedUser.id,
        rollNumber: dto.rollNumber,
        firstName: dto.firstName,
        lastName: dto.lastName,
        department: dto.department,
        enrollmentYear: dto.enrollmentYear,
        status: 'ACTIVE',
      });
      const savedStudent = await manager.save(Student, student);

      this.logger.log(`Student registered successfully with ID: ${savedStudent.id}`);
      return {
        message: 'Student registered successfully',
        student: savedStudent,
        user: { id: savedUser.id, email: savedUser.email, role: savedUser.role },
      };
    });
  }

  async findAll(page = 1, limit = 10) {
    const [items, total] = await this.studentRepository.findAndCount({
      relations: ['user'],
      skip: (page - 1) * limit,
      take: limit,
      order: { createdAt: 'DESC' },
    });
    return { data: items, meta: { total, page, limit, totalPages: Math.ceil(total / limit) } };
  }

  async findOne(id: string) {
    const student = await this.studentRepository.findOne({ where: { id }, relations: ['user'] });
    if (!student) throw new NotFoundException(`Student with ID '${id}' not found`);
    return student;
  }

  async update(id: string, dto: UpdateStudentDto) {
    const student = await this.findOne(id);
    Object.assign(student, dto);
    return await this.studentRepository.save(student);
  }

  async remove(id: string) {
    await this.findOne(id);
    await this.studentRepository.softDelete(id);
  }
}
💡 TIP: Transactions Prevent Partial Writes: Without dataSource.transaction(), if user creation succeeds but student creation fails due to a network glitch, you end up with a ghost user in the database who cannot log in. Transactions guarantee complete rollback!
⚠️ PITFALL: Salt Rounds: Salt rounds < 10 can be cracked in seconds on modern GPUs. Salt rounds > 14 will freeze Node.js CPU workers for hundreds of milliseconds per request. 10 to 12 is the industry standard.

src/auth/auth.service.tsimport { Injectable, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';

import { Repository } from 'typeorm';

import { User } from '../users/entities/user.entity';
import { LoginDto } from './dto/login.dto';
import { JwtPayload } from './interfaces/jwt-payload.interface';

@Injectable()
export class AuthService {
  constructor(
    @InjectRepository(User)
    private readonly userRepository: Repository<User>,
    private readonly jwtService: JwtService,
  ) {}

  async validateUser(email: string, pass: string): Promise<User> {
    const user = await this.userRepository.findOne({ where: { email } });
    if (!user) {
      throw new UnauthorizedException('Invalid credentials provided.');
    }

    const isMatch = await bcrypt.compare(pass, user.passwordHash);
    if (!isMatch) {
      throw new UnauthorizedException('Invalid credentials provided.');
    }

    return user;
  }

  async login(loginDto: LoginDto) {
    const user = await this.validateUser(loginDto.email, loginDto.password);

    const payload: JwtPayload = {
      sub: user.id,
      email: user.email,
      role: user.role,
    };

    return {
      accessToken: this.jwtService.sign(payload),
      tokenType: 'Bearer',
      expiresIn: '1h',
      user: { id: user.id, email: user.email, role: user.role },
    };
  }
}
⚠️ PITFALL: Never Expose JWT Secrets: Never commit JWT_SECRET to git or pass sensitive personal data in the JWT payload. The payload is Base64 encoded and visible to anyone inspecting the token!

JWT Strategy & Global Guard Setup

Security Architecture

By using @nestjs/passport and passport-jwt, incoming requests bearing an Authorization: Bearer <token> header are automatically parsed, verified against our secret, and the decoded payload is bound to req.user. 

src/auth/strategies/jwt.strategy.tsimport { Injectable, UnauthorizedException } from '@nestjs/common';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';
import { ConfigService } from '@nestjs/config';
import { JwtPayload } from '../interfaces/jwt-payload.interface';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor(configService: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false, // Automatically rejects expired tokens
      secretOrKey: configService.get<string>('JWT_SECRET'),
    });
  }

  // Whatever is returned here is attached to request.user
  async validate(payload: JwtPayload) {
    if (!payload.sub || !payload.role) {
      throw new UnauthorizedException('Malformed token payload');
    }
    return {
      id: payload.sub,
      email: payload.email,
      role: payload.role,
    };
  }
}

Step 4: Role-Based Access Control (RBAC) Guard

Authorization

After the JwtAuthGuard verifies identity and attaches req.user, the RolesGuard compares the user's role against permissions declared with the @Roles() decorator. 

src/auth/decorators/roles.decorator.tsimport { SetMetadata } from '@nestjs/common';
import { Role } from '../../common/enums/role.enum';

export const ROLES_KEY = 'roles';
// Attaches allowed roles metadata to route handler or controller class
export const Roles = (...roles: Role[]) => SetMetadata(ROLES_KEY, roles);
src/auth/guards/roles.guard.tsimport { Injectable, CanActivate, ExecutionContext, ForbiddenException } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { ROLES_KEY } from '../decorators/roles.decorator';
import { IS_PUBLIC_KEY } from '../../common/decorators/public.decorator';
import { Role } from '../../common/enums/role.enum';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    // 1. Bypass role check if route is public
    const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (isPublic) return true;

    // 2. Extract allowed roles metadata
    const requiredRoles = this.reflector.getAllAndOverride<Role[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);
    if (!requiredRoles || requiredRoles.length === 0) return true;

    // 3. Inspect authenticated user role from req.user
    const { user } = context.switchToHttp().getRequest();
    if (!user || !user.role) {
      throw new ForbiddenException('Access denied: Unauthenticated user identity.');
    }

    const hasRole = requiredRoles.includes(user.role);
    if (!hasRole) {
      throw new ForbiddenException(
        `Access denied: requires one of [${requiredRoles.join(', ')}]. Current role: '${user.role}'.`
      );
    }

    return true; // Authorized!
  }
}

Global Guard Ordering in AppModule

NestJS executes guards in the exact order declared in providers:

Step 5: Centralized Exception Filter & Request IDs

Resilience & Observability

Catch unexpected crashes, database constraints, and validation errors in a single centralized filter. It assigns a unique Correlation ID for distributed tracing and ensures consistent JSON responses. 

src/common/filters/all-exceptions.filter.tsimport { ExceptionFilter, Catch, ArgumentsHost, HttpException, HttpStatus, Logger } from '@nestjs/common';
import { Request, Response } from 'express';
import { randomUUID } from 'crypto';

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger(AllExceptionsFilter.name);

  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    // 1. Determine HTTP status code
    const status =
      exception instanceof HttpException
        ? exception.getStatus()
        : HttpStatus.INTERNAL_SERVER_ERROR;

    // 2. Extract message or response object
    let message: string | object = 'Internal server error occurred';
    if (exception instanceof HttpException) {
      const res = exception.getResponse();
      message = typeof res === 'object' && (res as any).message ? (res as any).message : res;
    } else if (exception instanceof Error) {
      message = exception.message;
    }

    // 3. Generate or preserve Request Correlation ID
    const correlationId = (request.headers['x-correlation-id'] as string) || randomUUID();
    response.setHeader('x-correlation-id', correlationId);

    // 4. Log error internally with stack trace
    const logPayload = `[${correlationId}] ${request.method} ${request.url} - Status: ${status}`;
    if (status >= 500) {
      this.logger.error(logPayload, exception instanceof Error ? exception.stack : '');
    } else {
      this.logger.warn(logPayload);
    }

    // 5. Send uniform sanitized JSON envelope to client
    response.status(status).json({
      success: false,
      statusCode: status,
      correlationId,
      timestamp: new Date().toISOString(),
      path: request.url,
      method: request.method,
      error: typeof message === 'string' ? message : (message as any).error || 'Error',
      details: Array.isArray(message) ? message : undefined,
    });
  }
}
⚠️ PITFALL: Leaking Raw SQL in Responses: Never return raw TypeORM QueryFailedError objects to clients in production! They reveal table names, column constraints, and SQL syntax to prospective attackers.
💡 TIP: Correlation IDs in Distributed Tracing: Passing x-correlation-id allows your support team and frontend developers to quote the exact ID from an error modal and find the exact backend log line in seconds!

Interceptors: Transformation & Serialization

Pipeline Transformations

Interceptors execute both before and after your route handler. We use them to measure execution performance, standardize responses into a consistent JSON envelope, and strip sensitive entity columns using ClassSerializerInterceptor. 

src/common/interceptors/transform.interceptor.tsimport { Injectable, NestInterceptor, ExecutionContext, CallHandler } from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';

export interface ResponseEnvelope<T> {
  success: boolean;
  statusCode: number;
  timestamp: string;
  data: T;
}

@Injectable()
export class TransformInterceptor<T> implements NestInterceptor<T, ResponseEnvelope<T>> {
  intercept(context: ExecutionContext, next: CallHandler): Observable<ResponseEnvelope<T>> {
    const statusCode = context.switchToHttp().getResponse().statusCode;

    return next.handle().pipe(
      map((data) => ({
        success: true,
        statusCode,
        timestamp: new Date().toISOString(),
        data,
      })),
    );
  }
}
src/common/interceptors/logging.interceptor.tsimport { Injectable, NestInterceptor, ExecutionContext, CallHandler, Logger } from '@nestjs/common';
import { Observable } from 'rxjs';
import { tap } from 'rxjs/operators';

@Injectable()
export class LoggingInterceptor implements NestInterceptor {
  private readonly logger = new Logger('HTTP');

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const req = context.switchToHttp().getRequest();
    const { method, url } = req;
    const now = Date.now();

    return next.handle().pipe(
      tap(() => {
        const elapsed = Date.now() - now;
        this.logger.log(`${method} ${url} completed in ${elapsed}ms`);
      }),
    );
  }
}

⚠️ CRITICAL PITFALL: Root Execution: Running containers as root gives anyone exploiting a remote code execution vulnerability root privileges over the host container runtime.

Master Production Bootstrap: main.ts

Architecture Synthesis

The complete src/main.ts file synthesizing all security layers: Helmet, CORS, Global Validation Pipe, Exception Filters, Serialization Interceptors, Winston Logger, and conditional Swagger documentation. 

src/main.tsimport { NestFactory, Reflector } from '@nestjs/core';
import { ValidationPipe, ClassSerializerInterceptor, Logger } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';
import helmet from 'helmet';
import { AppModule } from './app.module';
import { AllExceptionsFilter } from './common/filters/all-exceptions.filter';
import { TransformInterceptor } from './common/interceptors/transform.interceptor';
import { LoggingInterceptor } from './common/interceptors/logging.interceptor';

async function bootstrap() {
  const logger = new Logger('Bootstrap');
  const app = await NestFactory.create(AppModule);

  const configService = app.get(ConfigService);
  const port = configService.get<number>('PORT', 3000);
  const nodeEnv = configService.get<string>('NODE_ENV', 'development');

  // 1. Enable Graceful Shutdown hooks for container orchestrators (K8s/Docker)
  app.enableShutdownHooks();

  // 2. HTTP Security Headers with Helmet
  app.use(helmet());

  // 3. Strict Cross-Origin Resource Sharing (CORS)
  app.enableCors({
    origin: nodeEnv === 'production' ? ['https://sms-portal.university.edu'] : true,
    methods: ['GET', 'POST', 'PATCH', 'DELETE', 'OPTIONS'],
    credentials: true,
  });

  // 4. Global API Prefix
  app.setGlobalPrefix('api/v1');

  // 5. Global Validation Pipe
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,              // Strips unexpected fields injected by callers
      forbidNonWhitelisted: true,  // Rejects requests with unexpected fields
      transform: true,             // Coerces primitives automatically
      transformOptions: { enableImplicitConversion: true },
    }),
  );

  // 6. Global Interceptors (Serialization & Envelope)
  app.useGlobalInterceptors(
    new ClassSerializerInterceptor(app.get(Reflector)),
    new TransformInterceptor(),
    new LoggingInterceptor(),
  );

  // 7. Global Centralized Exception Filter
  app.useGlobalFilters(new AllExceptionsFilter());

  // 8. OpenAPI Swagger Documentation (Active in dev/test, disabled in prod)
  if (nodeEnv !== 'production') {
    const swaggerConfig = new DocumentBuilder()
      .setTitle('Student Management API')
      .setDescription('Enterprise Student Administration REST API with JWT Auth and RBAC')
      .setVersion('1.0.0')
      .addBearerAuth({ type: 'http', scheme: 'bearer', bearerFormat: 'JWT' }, 'JWT-auth')
      .build();
    const document = SwaggerModule.createDocument(app, swaggerConfig);
    SwaggerModule.setup('api/docs', app, document);
    logger.log(`Swagger documentation running at: http://localhost:${port}/api/docs`);
  }

  // 9. Bind server to 0.0.0.0 to accept container traffic
  await app.listen(port, '0.0.0.0');
  logger.log(`Application successfully listening on port ${port} [Env: ${nodeEnv}]`);
}
bootstrap();
💡 TIP: Listen on 0.0.0.0 in Docker: Always pass '0.0.0.0' as the host parameter in app.listen(port, '0.0.0.0'). Binding to default localhost (127.0.0.1) prevents Docker and Kubernetes ingress controllers from reaching the container!

Code Quality Pitfalls & Anti-Patterns Cheatsheet

Production Cheatsheet

A high-impact comparative reference contrasting battle-tested NestJS patterns against common beginner mistakes.

✔ The Do's (Production Best Practices)

  • Thin Controllers: Controllers only handle HTTP verbs, status codes, and call services.
  • Bcrypt Hashing: Always hash passwords using 10-12 salt rounds before persisting to database.
  • ConfigService + Joi: Validate all environment variables on startup so the app fails fast if keys are missing.
  • Structured Logger: Use new Logger(ClassName.name) or Winston for searchable, categorized logs.
  • Database Migrations: Use versioned TypeORM migrations with synchronize: false.
  • Throttler Guard: Apply rate limits (5 req/min on login) to prevent brute-force attacks.
  • ClassSerializerInterceptor: Automatically strip @Exclude() fields to protect password hashes.
  • Boundary Unit & E2E Tests: Test business logic with Jest mocks and endpoints with Supertest.
  • API Versioning: Always version endpoints using app.setGlobalPrefix('api/v1').
  • Strict DTOs: Use whitelist: true and forbidNonWhitelisted: true to stop mass-assignment.

✘ The Don'ts (Dangerous Anti-Patterns)

  • Fat Controllers: Writing raw SQL, password hashing, or loops directly in controller methods.
  • Plaintext Passwords: Persisting raw passwords or using weak md5/sha1 hashing algorithms.
  • Hardcoded Secrets: Inlining database passwords or JWT secrets directly into TypeScript files.
  • console.log(): Scattering console prints without timestamps, log levels, or correlation IDs.
  • synchronize: true in Prod: Auto-syncing schemas drops columns and permanently deletes production data.
  • No Rate Limiting: Leaving endpoints open to automated brute-force password stuffing.
  • Raw Entity Returns: Forgetting serializer interceptors, allowing password hashes to leak in JSON.
  • Zero Tests: Deploying without automated unit and E2E regression tests.
  • Unversioned APIs: Breaking existing mobile and web clients when endpoint signatures change.
  • Loose Any Payloads: Typing bodies as any, enabling parameter tampering and script injection.
