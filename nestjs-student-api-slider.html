Building REST APIs with NestJS

Case Study: Student Management

Welcome! In this module, you will learn how to design, architect, and code an enterprise-grade Student Management System (SMS) API from scratch using NestJS and TypeScript.

⚙ NestJS Architecture

Modular architecture inspired by Angular, built on Express/Fastify. Strong reliance on Dependency Injection, TypeScript decorators, and clean domain separation.

👥 Multi-Role Domain

Covers 3 distinct user roles:
• ADMIN (Registers & manages all)
• TEACHER (Grades & attendance)
• STUDENT (Views profile & courses)

NestJS Core Pillars & Request Lifecycle

Architecture

Every HTTP request in NestJS traverses a strictly organized, predictable pipeline:

Client Request
→
1. Middleware
→
2. Guards (RBAC)
→
3. Interceptors (Pre)
→
4. Pipes (Validation)
→
5. Controller
→
6. Service (Logic)
→
7. Response / Filter

The 3 Foundational Building Blocks

  • Modules (@Module()): Encapsulates related controllers and providers into self-contained units.
  • Controllers (@Controller()): Routes incoming HTTP requests (GET, POST, PUT, DELETE) and maps inputs.
  • Providers / Services (@Injectable()): Contains business logic, database queries, and external API calls. Injected via constructor DI.

Why This Architecture Wins

  • Zero Spaghetti Code: Clear separation between HTTP routing and business calculation.
  • Testability: Services are injected as dependencies, making unit testing and mocking trivial.
  • Production Standard: Enterprise standard for scalable Node.js microservices and REST backends.

Step 1: The DTO & Global Validation Pipe

Registration Pipeline

A DTO (Data Transfer Object) defines the exact network payload contract. Using class-validator decorators, incoming data is checked before it ever touches your controller. 

src/students/dto/create-student.dto.tsimport { IsEmail, IsNotEmpty, IsString, MinLength, IsNumber, Min, Max } from 'class-validator';

export class CreateStudentDto {
  @IsEmail({}, { message: 'Must be a valid educational or personal email' })
  email: string;

  @IsString()
  @MinLength(8, { message: 'Password must be at least 8 characters long' })
  password: string;

  @IsString()
  @IsNotEmpty({ message: 'First name is required' })
  firstName: string;

  @IsString()
  @IsNotEmpty({ message: 'Last name is required' })
  lastName: string;

  @IsString()
  @IsNotEmpty({ message: 'Roll number cannot be empty' })
  rollNumber: string;

  @IsString()
  @IsNotEmpty()
  department: string;

  @IsNumber()
  @Min(2020)
  @Max(2030)
  enrollmentYear: number;
}

Enable Global Auto-Validation in main.ts

src/main.tsimport { ValidationPipe } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  // Automatically strips unallowed properties & transforms types
  app.useGlobalPipes(
    new ValidationPipe({
      whitelist: true,              // Strips unexpected fields injected by attackers
      forbidNonWhitelisted: true,  // Throws 400 Bad Request on unknown fields
      transform: true,             // Automatically converts string query/body to DTO types
    }),
  );

  await app.listen(3000);
}

Step 2: The Controller Endpoint

Registration Pipeline

The controller defines the HTTP route, accepts the validated DTO, and delegates business logic execution to the service. 

src/students/students.controller.tsimport { Controller, Post, Body, HttpCode, HttpStatus, UseGuards } from '@nestjs/common';
import { StudentsService } from './students.service';
import { CreateStudentDto } from './dto/create-student.dto';
import { Roles } from '../auth/decorators/roles.decorator';
import { RolesGuard } from '../auth/guards/roles.guard';
import { JwtAuthGuard } from '../auth/guards/jwt-auth.guard';
import { Role } from '../common/enums/role.enum';

@Controller('students')
export class StudentsController {
  // Dependency Injection: NestJS automatically supplies the StudentsService singleton instance
  constructor(private readonly studentsService: StudentsService) {}

  @Post('register')
  @HttpCode(HttpStatus.CREATED) // Returns HTTP 201
  @UseGuards(JwtAuthGuard, RolesGuard) // Protects route: requires valid JWT & Role check
  @Roles(Role.ADMIN)                   // Only ADMIN role is authorized to register students
  async register(@Body() createStudentDto: CreateStudentDto) {
    return this.studentsService.registerStudent(createStudentDto);
  }
}
Clean Architecture Rule: Keep controllers thin! A controller should only handle HTTP routing, decorators, status codes, and delegate heavy lifting to the service.

Step 3: Service Business Logic & Hashing

Registration Pipeline

The service handles data validation rules (checking existing email or roll number duplicates), hashes the password with bcrypt, and stores the user and student profile. 

src/students/students.service.tsimport { Injectable, ConflictException } from '@nestjs/common';
import { CreateStudentDto } from './dto/create-student.dto';
import { Role } from '../common/enums/role.enum';
import * as bcrypt from 'bcrypt';

@Injectable()
export class StudentsService {
  // Simulated database repository (or TypeORM/Prisma client)
  private usersTable: any[] = [];
  private studentsTable: any[] = [];

  async registerStudent(dto: CreateStudentDto) {
    // 1. Check if email already registered
    const existingUser = this.usersTable.find((u) => u.email === dto.email);
    if (existingUser) {
      throw new ConflictException(`Email '${dto.email}' is already in use.`);
    }

    // 2. Check if roll number already assigned
    const existingRoll = this.studentsTable.find((s) => s.rollNumber === dto.rollNumber);
    if (existingRoll) {
      throw new ConflictException(`Roll number '${dto.rollNumber}' already exists.`);
    }

    // 3. Hash password with bcrypt (10 rounds of salt)
    const saltRounds = 10;
    const passwordHash = await bcrypt.hash(dto.password, saltRounds);

    // 4. Create base user record with STUDENT role
    const newUser = {
      id: `usr_${Date.now()}`,
      email: dto.email,
      passwordHash,
      role: Role.STUDENT,
      createdAt: new Date(),
    };
    this.usersTable.push(newUser);

    // 5. Create student profile linked to the user
    const newStudent = {
      id: `std_${Date.now()}`,
      userId: newUser.id,
      firstName: dto.firstName,
      lastName: dto.lastName,
      rollNumber: dto.rollNumber,
      department: dto.department,
      enrollmentYear: dto.enrollmentYear,
      status: 'ACTIVE',
    };
    this.studentsTable.push(newStudent);

    // 6. Return sanitized response WITHOUT password hash
    return {
      message: 'Student registered successfully',
      student: newStudent,
      user: { id: newUser.id, email: newUser.email, role: newUser.role },
    };
  }
}

Step 4: Role-Based Access Control (RBAC)

Registration Pipeline

To prevent unauthorized registrations, we enforce Role-Based Access Control using a custom @Roles() decorator and a RolesGuard. 

src/auth/decorators/roles.decorator.tsimport { SetMetadata } from '@nestjs/common';
import { Role } from '../../common/enums/role.enum';

export const ROLES_KEY = 'roles';
// Custom decorator attaching metadata to route handlers
export const Roles = (...roles: Role[]) => SetMetadata(ROLES_KEY, roles);
src/auth/guards/roles.guard.tsimport { Injectable, CanActivate, ExecutionContext, ForbiddenException } from '@nestjs/common';
import { Reflector } from '@nestjs/core';
import { ROLES_KEY } from '../decorators/roles.decorator';
import { Role } from '../../common/enums/role.enum';

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.getAllAndOverride<Role[]>(ROLES_KEY, [
      context.getHandler(),
      context.getClass(),
    ]);

    if (!requiredRoles) return true; // No roles needed for this route

    const { user } = context.switchToHttp().getRequest();
    if (!user || !requiredRoles.includes(user.role)) {
      throw new ForbiddenException('Forbidden: Insufficient role permissions.');
    }

    return true; // Authorized!
  }
}

Step 5: Global Exception Filter & Standard Responses

Registration Pipeline

Catch unexpected crashes, database constraints, and validation errors in a single centralized filter, formatting errors into a consistent JSON envelope. 

src/common/filters/http-exception.filter.tsimport { ExceptionFilter, Catch, ArgumentsHost, HttpException, HttpStatus } from '@nestjs/common';
import { Request, Response } from 'express';

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const ctx = host.switchToHttp();
    const response = ctx.getResponse<Response>();
    const request = ctx.getRequest<Request>();

    const status =
      exception instanceof HttpException
        ? exception.getStatus()
        : HttpStatus.INTERNAL_SERVER_ERROR;

    const message =
      exception instanceof HttpException
        ? exception.getResponse()
        : 'Internal Server Error';

    response.status(status).json({
      success: false,
      statusCode: status,
      timestamp: new Date().toISOString(),
      path: request.url,
      error: message,
    });
  }
}

Step 6: Authentication & JWT Verification

Security

How does the RolesGuard know who is calling the endpoint? The client sends a signed JWT in the Authorization: Bearer <token> header. 

src/auth/auth.service.tsimport { Injectable, UnauthorizedException } from '@nestjs/common';
import { JwtService } from '@nestjs/jwt';
import * as bcrypt from 'bcrypt';

@Injectable()
export class AuthService {
  constructor(private jwtService: JwtService) {}

  async login(user: any) {
    // Payload embedded inside the JWT signature
    const payload = {
      sub: user.id,
      email: user.email,
      role: user.role, // 'ADMIN' | 'TEACHER' | 'STUDENT'
    };

    return {
      accessToken: this.jwtService.sign(payload, { expiresIn: '8h' }),
      user: { id: user.id, email: user.email, role: user.role },
    };
  }
}

JWT Passport Strategy (jwt.strategy.ts)

Decodes and verifies the token on incoming requests and automatically attaches the payload to request.user: 

// Returns user payload to request.user
async validate(payload: { sub: string; email: string; role: Role }) {
  return { id: payload.sub, email: payload.email, role: payload.role };

Step 7: Swagger / OpenAPI Auto-Documentation

Documentation

NestJS provides first-class OpenAPI documentation. Decorate your DTOs and controllers to generate an interactive API testing interface at /api/docs. 

src/main.tsimport { DocumentBuilder, SwaggerModule } from '@nestjs/swagger';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);

  const config = new DocumentBuilder()
    .setTitle('Student Management API')
    .setDescription('Complete SMS REST API with RBAC roles and registration')
    .setVersion('1.0')
    .addBearerAuth() // Allows passing JWT token in Swagger UI
    .build();

  const document = SwaggerModule.createDocument(app, config);
  SwaggerModule.setup('api/docs', app, document);

  await app.listen(3000);
}

Summary & Production Best Practices

Cheatsheet

✔ The Do's of NestJS APIs

  • Always validate with DTOs: Use class-validator and enable whitelist: true to stop parameter pollution.
  • Inject Services: Keep business calculations in @Injectable() classes.
  • Secure by Default: Bind JwtAuthGuard globally or per controller, opt-out with @Public() metadata.
  • Hash early, sanitize late: Use bcrypt.hash(password, 10) and exclude hashes from responses.
  • Centralize errors: Implement global exception filters for uniform API error structures.

✘ Anti-Patterns to Avoid

  • Fat Controllers: Writing raw database queries or loops directly in controller route handlers.
  • Plain Text Passwords: Never store or log raw user passwords.
  • Hardcoding Secrets: Always use @nestjs/config (ConfigService) for environment variables.
  • Direct Component Coupling: Avoid direct class instantiation (new Service()); use dependency injection.
