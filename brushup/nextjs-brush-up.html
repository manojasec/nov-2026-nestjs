1. Introduction & Rendering Paradigms

Next.js is a full-stack React framework that shifts heavy compute and data retrieval to the server, delivering minimal client bundles, instant page loads, and native SEO.

Paradigm Where Rendered When Rendered Best For
RSC (React Server Components) Server only Build or Request time Default in App Router. Zero JS sent to browser. DB queries, markdown, heavy libs.
SSR (Server-Side Rendering) Server on demand Every HTTP Request Personalized feeds, auth dashboards, real-time dynamic data.
SSG (Static Site Generation) Server / Build At npm run build Blogs, docs, marketing sites, e-commerce catalog pages.
ISR (Incremental Static Revalidation) Server background Periodic revalidation High-traffic pages with periodic updates (e.g. revalidate every 60s).
CSR (Client-Side Rendering) Browser User interaction time Buttons, forms with live state, modal toggles, browser APIs (canvas, audio).

App Router vs. Pages Router

Feature App Router (app/) Pages Router (pages/ legacy)
Default Component Server Component Client Component
Data Fetching Native async/await in component getServerSideProps, getStaticProps
Layouts Nested, preserve state during transitions Manual wrappers (re-mount on route change)
Data Mutations Server Actions ('use server') API route endpoints + client fetch
Streaming Native with React Suspense & loading.tsx Difficult / external libraries

3. App Router & Layouts

Next.js uses folder-based routing where the folder structure maps directly to the URL pathname. Special reserved filenames define UI boundaries:

Root Layout (app/layout.tsx)

Mandatory for the app. Must define <html> and <body> tags. It never re-renders on route transitions.

// src/app/layout.tsx
import type { Metadata } from "next";
import { Inter } from "next/font/google";
import "./globals.css";

const inter = Inter({ subsets: ["latin"] });

export const metadata: Metadata = {
  title: {
    template: "%s | Acme Corp",
    default: "Acme Corp - NextGen Cloud",
  },
  description: "Enterprise high-performance cloud platform",
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en" className={inter.className}>
      <body className="bg-slate-950 text-slate-100 min-h-screen">
        <header className="border-b border-slate-800 p-4">
          <nav>Shared Global Navbar</nav>
        </header>
        <main>{children}</main>
        <footer className="p-4 text-center text-sm text-slate-500">
          © 2026 Acme Corp
        </footer>
      </body>
    </html>
  );
}

Nested Layouts

Folders can have their own layout.tsx. It wraps child routes and preserves its internal state during sibling navigations. 

// src/app/dashboard/layout.tsx
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div className="flex h-screen">
      <aside className="w-64 border-r border-slate-800 p-4">
        <h3>Dashboard Menu</h3>
        {/* Navigation links here */}
      </aside>
      <section className="flex-1 p-8 overflow-y-auto">
        {children}
      </section>
    </div>
  );
}
Layout vs Template: layout.tsx persists state across page changes (form inputs retain values). If you want a fresh component instance and fresh animations on every navigation, rename it to template.tsx!

Next.js 15 Async Params & Pre-rendering

Next.js 15+ In Next.js 15, params and searchParams are Promises that must be awaited. 

// src/app/blog/[id]/page.tsx
import { notFound } from "next/navigation";

interface PageProps {
  params: Promise<{ id: string }>;
  searchParams: Promise<{ filter?: string }>;
}

// Generate static routes at build time (SSG for dynamic routes)
export async function generateStaticParams() {
  const posts = [{ id: "1" }, { id: "2" }, { id: "3" }];
  return posts.map((post) => ({ id: post.id }));
}

export default async function BlogPostPage({ params, searchParams }: PageProps) {
  const { id } = await params;
  const { filter } = await searchParams;

  if (Number(id) > 1000) {
    notFound(); // Triggers not-found.tsx
  }

  return (
    <article>
      <h1>Post #{id}</h1>
      {filter && <p>Applied filter: {filter}</p>}
    </article>
  );
}

5. Server Components vs. Client Components

By default in the App Router, every component is a Server Component. To make a component interactive, declare 'use client' at the very top of the file.

Capability Server Component Client Component ('use client')
Direct Database & File System access Yes (Prisma, Drizzle, SQL, fs) No (Security leak!)
Secrets & API keys without NEXT_PUBLIC_ Yes (Safe) No (Exposed in bundle)
React Hooks (useState, useEffect, useReducer) No Yes
Event Listeners (onClick, onChange) No Yes
Browser APIs (window, localStorage, navigator) No Yes (inside useEffect)
Bundle size impact 0 KB JavaScript sent to client Included in client bundle

The Component Composition Rule (The Golden Rule)

A Client Component cannot directly import a Server Component! However, you can pass a Server Component as children or as a prop. 

// ❌ INVALID: Client component directly imports Server Component
'use client';
import HeavyServerDbReader from './HeavyServerDbReader'; // ERROR: Pulls server code into bundle!

export default function ClientModal() {
  return <div><HeavyServerDbReader /></div>;
}
// ✅ CORRECT: Pass Server Component via children
// src/components/ClientModal.tsx
'use client';
import { useState } from 'react';

export default function ClientModal({ children }: { children: React.ReactNode }) {
  const [isOpen, setIsOpen] = useState(false);
  return (
    <div>
      <button onClick={() => setIsOpen(!isOpen)}>Toggle Modal</button>
      {isOpen && <div className="modal">{children}</div>}
    </div>
  );
}

// In app/page.tsx (Server Component):
import ClientModal from '@/components/ClientModal';
import HeavyServerDbReader from '@/components/HeavyServerDbReader';

export default function Page() {
  return (
    <ClientModal>
      {/* HeavyServerDbReader executes on server, only rendered HTML goes into modal slot */}
      <HeavyServerDbReader />
    </ClientModal>
  );
}

6. Data Fetching & Streaming

In Server Components, simply use standard async/await. You do not need useEffect or Axios! 

// Runnable Simulation of Next.js Parallel Fetching vs Waterfall
async function fetchUser() {
  return new Promise((res) => setTimeout(() => res({ id: 1, name: "Alice" }), 150));
}
async function fetchPosts() {
  return new Promise((res) => setTimeout(() => res([{ id: 101, title: "Next.js Rocks" }]), 200));
}

// ❌ Waterfall: awaits sequentially (takes 150ms + 200ms = 350ms)
console.time("Waterfall Fetch");
const user1 = await fetchUser();
const posts1 = await fetchPosts();
console.timeEnd("Waterfall Fetch");
console.log("Waterfall got:", user1.name, posts1[0].title);

// ✅ Parallel: awaits concurrently with Promise.all (takes ~200ms)
console.time("Parallel Fetch");
const [user2, posts2] = await Promise.all([fetchUser(), fetchPosts()]);
console.timeEnd("Parallel Fetch");
console.log("Parallel got:", user2.name, posts2[0].title);

Next.js Extended fetch Cache Options

// 1. Static fetch (cached indefinitely, SSG)
const staticData = await fetch('https://api.example.com/items', {
  cache: 'force-cache', // Default in Next.js 14
});

// 2. Dynamic fetch on every request (no cache, SSR)
const liveData = await fetch('https://api.example.com/stocks', {
  cache: 'no-store', // Default in Next.js 15
});

// 3. Time-based revalidation (ISR)
const isrData = await fetch('https://api.example.com/products', {
  next: { revalidate: 60 }, // Revalidate every 60 seconds
});

// 4. Tag-based on-demand revalidation
const taggedData = await fetch('https://api.example.com/cart', {
  next: { tags: ['user-cart'] },
});

Streaming with React Suspense

Stream parts of the page as soon as they become ready, preventing slow database queries from blocking the rest of the UI. 

// src/app/dashboard/page.tsx
import { Suspense } from 'react';
import FastHeader from '@/components/FastHeader';
import SlowAnalytics from '@/components/SlowAnalytics';
import AnalyticsSkeleton from '@/components/AnalyticsSkeleton';

export default function DashboardPage() {
  return (
    <div>
      {/* FastHeader renders instantly */}
      <FastHeader />

      {/* SlowAnalytics streams in once ready without delaying FastHeader */}
      <Suspense fallback={<AnalyticsSkeleton />}>
        <SlowAnalytics />
      </Suspense>
    </div>
  );
}

7. Server Actions & Mutations

Server Actions are asynchronous functions executed on the server. They can be invoked directly from HTML forms or client components without creating manual API endpoints.

Dedicated Action File (actions.ts)

// src/app/actions.ts
'use server';

import { revalidatePath } from 'next/cache';
import { z } from 'zod';

const TaskSchema = z.object({
  title: z.string().min(3, "Title must be at least 3 characters"),
});

export async function createTask(prevState: any, formData: FormData) {
  const rawTitle = formData.get('title');
  const result = TaskSchema.safeParse({ title: rawTitle });

  if (!result.success) {
    return {
      success: false,
      errors: result.error.flatten().fieldErrors,
    };
  }

  // Simulated DB insertion
  // await db.task.create({ data: { title: result.data.title } });

  // Invalidate cache for the task page
  revalidatePath('/tasks');

  return { success: true, message: `Task "${result.data.title}" added!` };
}

Client Form with useActionState & useFormStatus

// src/components/TaskForm.tsx
'use client';

import { useActionState } from 'react';
import { useFormStatus } from 'react-dom';
import { createTask } from '@/app/actions';

function SubmitButton() {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending} className="bg-sky-500 px-4 py-2 rounded font-bold">
      {pending ? 'Saving...' : 'Add Task'}
    </button>
  );
}

export default function TaskForm() {
  const [state, formAction] = useActionState(createTask, null);

  return (
    <form action={formAction} className="space-y-4">
      <input
        name="title"
        placeholder="Enter task title"
        className="bg-slate-900 border border-slate-700 p-2 rounded"
      />
      {state?.errors?.title && (
        <p className="text-red-400 text-sm">{state.errors.title[0]}</p>
      )}
      <SubmitButton />
      {state?.success && <p className="text-emerald-400">{state.message}</p>}
    </form>
  );
}

8. Caching & Revalidation

Next.js features a multi-tiered caching architecture designed for extreme performance.

Mechanism Where Stored Purpose Duration
Request Memoization Server Memory Deduplicates identical fetch() calls across the same render pass Lifetime of a single HTTP request
Data Cache Server Persistent Store Stores data across distinct user requests and builds Persistent until revalidated
Full Route Cache Server HTML/RSC payload Caches rendered HTML and RSC payload of static routes Persistent until revalidation
Router Cache Client browser memory Stores visited RSC payloads for instant back/forward navigation User session (seconds)

Programmatic Cache Invalidation

// Demonstrating tag-based and path-based invalidation logic
interface CacheStore {
  [key: string]: { tag: string; value: any; timestamp: number };
}

const mockCache: CacheStore = {
  "/products": { tag: "products", value: ["MacBook", "iPad"], timestamp: Date.now() },
  "/products/1": { tag: "products", value: "MacBook Pro", timestamp: Date.now() },
  "/cart": { tag: "cart", value: ["Item 1"], timestamp: Date.now() },
};

function revalidateTag(targetTag: string) {
  let cleared = 0;
  for (const [key, item] of Object.entries(mockCache)) {
    if (item.tag === targetTag) {
      delete mockCache[key];
      cleared++;
    }
  }
  return `Revalidated tag '${targetTag}': cleared ${cleared} cache entries.`;
}

console.log("Before:", Object.keys(mockCache));
console.log(revalidateTag("products"));
console.log("After:", Object.keys(mockCache));

9. Route Handlers (API Endpoints)

Defined in app/api/**/route.ts. Replaces traditional Express routes or Pages router API endpoints. 

// src/app/api/users/[id]/route.ts
import { NextRequest, NextResponse } from "next/server";

interface RouteContext {
  params: Promise<{ id: string }>;
}

// GET /api/users/:id
export async function GET(request: NextRequest, context: RouteContext) {
  const { id } = await context.params;
  const searchParams = request.nextUrl.searchParams;
  const detail = searchParams.get("detail");

  return NextResponse.json({
    id,
    name: "John Doe",
    detail: detail === "true",
  });
}

// POST /api/users/:id
export async function POST(request: NextRequest, context: RouteContext) {
  const { id } = await context.params;
  const body = await request.json();

  if (!body.email) {
    return NextResponse.json(
      { error: "Email is required" },
      { status: 400 }
    );
  }

  return NextResponse.json(
    { message: `User ${id} updated`, data: body },
    { status: 201, headers: { "X-Processed-By": "NextJS-AppRouter" } }
  );
}

10. Middleware

Middleware runs before a request is completed, at the Edge. It is ideal for authentication redirects, bot protection, header decoration, and A/B testing. 

// middleware.ts (in root or src/)
import { NextResponse } from 'next/server';
import type { NextRequest } from 'next/server';

export function middleware(request: NextRequest) {
  const token = request.cookies.get('session_token')?.value;
  const pathname = request.nextUrl.pathname;

  // Protect all /dashboard routes
  if (pathname.startsWith('/dashboard') && !token) {
    const loginUrl = new URL('/login', request.url);
    loginUrl.searchParams.set('from', pathname);
    return NextResponse.redirect(loginUrl);
  }

  // Inject a custom response header or pass through
  const response = NextResponse.next();
  response.headers.set('X-Request-Path', pathname);
  return response;
}

// Matcher configuration restricts where middleware executes
export const config = {
  matcher: [
    '/dashboard/:path*',
    '/api/protected/:path*',
    // Exclude static assets, favicon, _next
    '/((?!_next/static|_next/image|favicon.ico).*)',
  ],
};

// 2. Programmatic Navigation in Client Components
'use client';
import { useRouter, usePathname, useSearchParams } from 'next/navigation';

export function SearchBox() {
  const router = useRouter();
  const pathname = usePathname();
  const searchParams = useSearchParams();

  const handleSearch = (term: string) => {
    const params = new URLSearchParams(searchParams.toString());
    if (term) params.set('q', term);
    else params.delete('q');
    router.push(`${pathname}?${params.toString()}`);
  };

  return <input onChange={(e) => handleSearch(e.target.value)} />;
}

14. Authentication & Security Best Practices

Security Concern Incorrect Approach Best Practice
Server Secrets & DB Keys Naming NEXT_PUBLIC_SECRET_KEY Omit prefix: SECRET_KEY. Use import 'server-only' to guarantee it never reaches client.
Route Protection Only checking auth in client useEffect Check session in middleware.ts AND verify in Server Component/Action.
Session Tokens Storing tokens in localStorage Store in HttpOnly, Secure, SameSite=Lax cookies.
Server Action Input Trusting formData blindly Always parse with Zod or a validator schema before mutating DB.

15. Suspense & Error Boundaries

Next.js provides automatic nested error boundaries via error.tsx.

// src/app/dashboard/error.tsx
'use client'; // Error boundaries MUST be Client Components

import { useEffect } from 'react';

export default function ErrorBoundary({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    console.error('Logged to monitoring service:', error);
  }, [error]);

        className="mt-4 px-4 py-2 bg-red-600 rounded font-semibold text-white"
      >
        Try Again
      </button>
    </div>
  );
}

17. Next.js 15 Key Updates

Breaking Change in Next.js 15: Runtime request APIs that rely on incoming requests (like cookies(), headers(), params, and searchParams) are now asynchronous and return a Promise. 
// ❌ Next.js 14 Style (Deprecation warning or runtime error in Next.js 15)
import { cookies } from 'next/headers';

export default function Page({ params }: { params: { id: string } }) {
  const cookieStore = cookies(); // ERROR: cookies() must be awaited!
  const token = cookieStore.get('token');
  return <div>Post: {params.id}</div>; // ERROR: params must be awaited!
}
// ✅ Next.js 15 Style (Async await)
import { cookies, headers } from 'next/headers';

interface Props {
  params: Promise<{ id: string }>;
  searchParams: Promise<{ q?: string }>;
}

export default async function Page({ params, searchParams }: Props) {
  const cookieStore = await cookies();
  const headerStore = await headers();
  const { id } = await params;
  const { q } = await searchParams;

  const token = cookieStore.get('token')?.value;
  const userAgent = headerStore.get('user-agent');

  return (
    <div>
      <h1>Item {id}</h1>
      <p>Search: {q}</p>
    </div>
  );
}

18. Common Pitfalls & Solutions

Pitfall 1: Hydration Mismatch

Occurs when HTML generated on the server differs from the initial client render (e.g. using Date.now(), Math.random(), or reading window).

// ❌ Hydration Error: Server renders UTC timestamp, browser renders user local time
export default function Clock() {
  return <p>Current time: {new Date().toLocaleTimeString()}</p>;
}
// ✅ Solution: Render time only after client mounts
'use client';
import { useState, useEffect } from 'react';

export default function SafeClock() {
  const [time, setTime] = useState<string | null>(null);

  useEffect(() => {
    setTime(new Date().toLocaleTimeString());
  }, []);

  return <p>Current time: {time ?? "Loading time..."}</p>;
}

Pitfall 2: Wrapping redirect() inside try/catch

// ❌ BUG: Next.js redirect() throws an internal NEXT_REDIRECT error
export async function myAction() {
  'use server';
  try {
    // some code
    redirect('/done'); // Catch block catches NEXT_REDIRECT and breaks the redirect!
  } catch (err) {
    console.error("Failed", err);
  }
}

Exercise 2: Type-Safe Server Action with Zod and Optimistic Updates

Problem: Build a task completion toggle that optimistically updates the checkbox in the UI before the server mutation completes, and rolls back if an error occurs.

// Solution:
'use client';
import { useOptimistic, useTransition } from 'react';
import { toggleTaskCompletion } from '@/app/actions';

interface Task {
  id: string;
  title: string;
  done: boolean;
}

export function TaskItem({ task }: { task: Task }) {
  const [isPending, startTransition] = useTransition();
  const [optimisticTask, setOptimisticTask] = useOptimistic(
    task,
    (current, update: boolean) => ({ ...current, done: update })
  );

  return (
    <label className="flex items-center gap-2">
      <input
        type="checkbox"
        checked={optimisticTask.done}
        disabled={isPending}
        onChange={() => {
          startTransition(async () => {
            setOptimisticTask(!optimisticTask.done);
            await toggleTaskCompletion(task.id, !optimisticTask.done);
          });
        }}
      />
      <span className={optimisticTask.done ? "line-through text-slate-500" : ""}>
        {optimisticTask.title}
      </span>
    </label>
  );
}
